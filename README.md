# re:silience — 웹 복원력 관찰실

실제 동작하는 로컬 포털에 장애를 주입하고, 같은 요청의 서버 기록과 브라우저 반응을 연결해서 관찰하는 프로젝트입니다. 응답시간이나 시세를 난수로 생성하지 않습니다. 성공/실패 판정에 임의의 응답시간 기준을 사용하지 않습니다.

## 실행

Node.js와 npm이 설치된 환경에서 터미널 두 개를 사용합니다.

```powershell
cd backend
npm install
npm run dev
```

```powershell
cd frontend
npm install
npm run dev
```

프런트엔드에 표시되는 로컬 주소를 엽니다. API 기본 포트는 3000입니다. 다른 프로그램이나 이전 API 서버가 점유하고 있으면 해당 프로그램을 확인한 후 종료하거나, API의 `PORT`와 프런트엔드의 `API_TARGET`을 함께 변경합니다. 기본 바인딩은 `127.0.0.1`이며 인터넷에 공개하도록 설계하지 않았습니다.

```powershell
# API 터미널
$env:PORT = '3100'
npm start

# 프런트엔드 터미널
$env:API_TARGET = 'http://127.0.0.1:3100'
npm run dev -- --port 5175
```

공개 데모 계정은 `demo@resilience.local` / `resilience`, 표시 이름은 `karylyuu`입니다. 세션은 서버에서 확인하며 1시간 유효합니다. 실제 개인정보를 입력하지 마세요. 카페 글·댓글·공감은 `backend/data/community.json`에 보관합니다. 계정 가입·찾기 기능을 구현한 것처럼 표시하지 않습니다.

## 관찰 절차

1. 장애가 꺼진 상태에서 평소처럼 뉴스·검색·카페를 사용합니다. 홈의 연결 확인 API는 관측용으로 3초마다 요청됩니다.
2. 같은 요청의 **주입 전** 표본이 모였는지 관측·비교 탭에서 확인합니다. 표본 수나 시간에 합격선을 두지 않습니다.
3. 장애를 선택하고 같은 기능을 사용합니다. **주입 중** 기록에 실제 HTTP 결과, 서버 소요시간, 브라우저 해석/자원 수신 결과가 쌓입니다.
4. 전체 해제 또는 개별 해제 후 같은 요청을 다시 실행합니다. **해제 후** 표본과 주입 전 분포를 비교합니다. 해제 버튼을 눌렀다는 이유만으로 복원 완료를 선언하지 않습니다.
5. 진단 펼치기에서 변경 시각, 구간별 조합, 자원 지표, 브라우저 이벤트를 확인하고 엑셀로 저장합니다.

`새 관찰`은 기존 세션 기록을 지우지 않고 새 관찰 ID로 분리합니다. 전체 세션 내보내기는 관찰 ID별 비교를 유지합니다. 기록은 유형별 최근 12,000개를 메모리에 보관하고 초과분은 누락 개수로 표시합니다. **서버 재시작 전 저장하세요.** 카페 저장과 달리 관측 기록은 자동 영구 저장하지 않습니다.

## 장애가 작동하는 위치

| 주입                  | 실제 구현                                                         | 범위와 해석상 한계                                                                     |
| --------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| API 지연·대기         | 사용자 입력 시간 동안 처리를 보류하거나, 해제까지 요청을 대기시킴 | 입력값은 주입량이지 측정 결과/정상 기준이 아님. 실제 응답시간은 별도 측정              |
| API 오류 응답         | JSON 경로에 HTTP 503 반환                                         | 설정한 오류 응답이며 자연 발생 장애 원인을 재현했다고 주장하지 않음                    |
| 응답 연결 끊김        | 서비스 요청의 HTTP 소켓 종료                                      | 실제 IP 패킷 손실·네트워크 장비 장애가 아님. 개발 프록시는 500으로 바꿔 전달할 수 있음 |
| 응답 데이터 손상      | JSON을 잘린 본문으로 전송                                         | HTTP 200과 브라우저 JSON 파싱 실패를 분리해 관찰                                       |
| 이미지 전달 실패      | 로컬 SVG 요청 503                                                 | 이미 받은 이미지는 유지될 수 있음. 다시 요청할 때 변화 확인                            |
| 스타일 파일 전달 실패 | 포털 전용 CSS 요청 503                                            | `이미지·스타일 다시 받기`는 기존 CSS를 떼고 새 요청. 재요청 전 이미 적용된 CSS는 남음  |
| CPU 연산 경합         | API 프로세스에서 PBKDF2 해시 연산과 이벤트 루프 양보를 반복       | 프로세스의 제한된 CPU 경쟁. 시스템 전체 고갈을 가장하지 않음                           |
| 메모리 점유 증가      | 실제 버퍼 64 MiB를 할당/접촉하고 유지                             | 안전하게 제한된 점유 증가. OOM 아님. 참조 해제 후 RSS가 즉시 줄지 않을 수 있음         |

모든 장애는 **60초 뒤 자동 해제**됩니다. API 지연 입력은 1~10,000 ms, 미입력은 수동 해제까지 대기입니다. 클라이언트 요청 제한은 20초, 공급자 요청 제한은 8초입니다. 이는 안전·대기 제한이지 성능 판정 기준이 아닙니다. 단일 장애의 효과를 분리해서 보려면 새 관찰을 사용하세요. 조합 실험도 지원하지만 앞 단계의 오류가 뒤 단계 실행을 막을 수 있습니다.

진단·제어 경로는 장애 미들웨어를 지나지 않습니다. 다만 CPU와 메모리는 같은 서버 프로세스를 공유하므로 제어 요청 자체도 자원 경합 영향을 받을 수 있습니다. 진단 패널의 스타일은 실험용 포털 CSS와 분리했습니다.

## 관측 데이터의 의미

- 서버 요청시간: `performance.now()`로 시작부터 전송 완료 또는 연결 종료까지 측정. 성공 응답은 브라우저의 최종 렌더 완료를 보장하지 않습니다.
- 단계: 요청 시작/끝 사이에 장애 설정이 바뀌면 `전환 교차`로 표시하고 단계별 평균에서 제외합니다. 원본은 남깁니다.
- 실패 비율: HTTP 400 이상 또는 연결 종료 건수 / 종료된 요청 수. 브라우저 JSON 해석 오류는 별도 이벤트입니다.
- CPU: 서버 프로세스 CPU 시간 / 실제 측정 간격. 100%는 논리 코어 하나이며 운영체제 전체 CPU 비율이 아닙니다.
- RSS/Heap: Node.js 프로세스 실측 메모리. 관측·엑셀 처리의 사용량도 포함됩니다.
- 이벤트 루프 지연: 1초 측정 타이머가 실제로 초과한 시간입니다. 브라우저 렌더링 지연과 다릅니다.
- 브라우저: API 수신/해석, 이미지 load/error, 스타일 link load/error 이벤트. 요청 ID로 서버 기록과 연결합니다. 전달 실패 건수는 브라우저에 따로 경고합니다. 페이지 이동으로 취소된 요청도 실제 취소로 남습니다.
- 선/막대/산점도는 실측값으로만 구성합니다. 표본이 없으면 빈 상태로 표시합니다. 상관관계만으로 단일 원인이나 복원 합격을 단정하지 않습니다.

화면에는 최근 요청 600개, 자원 표본 180개, 브라우저 이벤트 100개를 전달합니다. 비교 요약은 현재 관찰의 보관 중인 전체 표본으로 계산하며, 엑셀에는 선택한 범위의 보관 원본을 내보냅니다. 화면 표시 개수와 전체 보관 개수는 다를 수 있습니다.

엑셀은 `.xlsx`로 생성합니다. 읽는 방법, 관측 차트, 경로별 비교, 요청 원본, 자원 원본, 브라우저 관찰, 장애 전환, 설정 구간별 비교의 8개 시트를 포함합니다. 차트는 원본 셀에 연결한 네이티브 XY 차트입니다. 요약값은 내보낸 시점의 계산 결과이며 원본 수정 시 자동 재계산되는 수식표가 아닙니다. 날짜는 UTC, 수치는 숫자 셀로 저장합니다.

## 외부 데이터와 서비스

- 뉴스: [연합뉴스 RSS](https://www.yna.co.kr/rss/news.xml), [BBC Technology RSS](https://feeds.bbci.co.uk/news/technology/rss.xml), [CoinDesk RSS](https://www.coindesk.com/arc/outboundfeeds/rss/). 제목·출처·발행시각·원문 링크만 사용합니다. 약 60초 간격 확인이며 새 기사가 없으면 내용이 그대로인 것이 정상입니다.
- 코인: [Upbit 현재가 API](https://docs.upbit.com/kr/reference/list-tickers), KRW-BTC/ETH/XRP. 화면 조회 간격 15초, 서버 캐시 5초. WebSocket 체결 스트림이 아닌 스냅샷 조회입니다.
- 환율: [Frankfurter](https://frankfurter.dev/)의 ECB 일별 기준환율. EUR 기준 USD/JPY/KRW를 같은 날짜의 교차환율로 계산합니다. 1 USD 및 1 JPY의 원화값이며 실시간 거래 환율이 아닙니다.
- 지도: Leaflet + OpenStreetMap. 확대/이동, 수동 좌표, 브라우저 위치 권한 기반 현재 위치를 지원합니다. 길찾기·실시간 교통은 미구현입니다. 위치 좌표는 실험 서버에 기록하지 않지만 해당 지역 지도 타일은 외부에 요청합니다.
- 영상: YouTube 공식 임베드. 기본 영상은 사용자가 지정한 [灰色と青 — yurisa cover](https://www.youtube.com/watch?v=ieGKMldpp-M)입니다. 다른 영상 주소를 적용하면 같은 탭에서 메뉴 이동·새로고침 후에도 선택을 유지합니다. 같은 주소를 다시 적용해 재시도할 수도 있습니다. 제공자 정책에 따른 재생 제한은 우회하지 않습니다.

외부 공급자를 받지 못하면 실패 또는 마지막 수신값과 수신 시각을 표시합니다. 가짜 기사·시세로 대체하지 않습니다. 지도와 YouTube는 브라우저가 외부에 직접 연결하므로 **로컬 API 장애 대상이나 관측 성공으로 간주하지 않습니다.** 공개 호스팅 전 각 제공자의 이용 조건과 호출 정책을 검토해야 합니다.

## 개발 및 검증

```powershell
npm run check --prefix backend
npm test --prefix backend
npm run lint --prefix frontend
npm run build --prefix frontend
```

통합 테스트는 별도 API 포트 3197과 임시 데이터 폴더를 사용합니다. 테스트 종료 후 생성한 임시 데이터만 정리합니다. 요청 지연/해제, 전환 교차, HTTP 오류, 손상 JSON, 이미지/CSS, 연결 종료, 제한된 자원 점유, 인증·카페 저장, 엑셀 원본·차트 구조, 교차 출처 차단을 확인합니다.

현재 설계는 로컬 복원력 관찰용입니다. 실제 해킹 도구나 외부 대상 공격, 운영체제 패킷 손실, PC 메모리 소진, 전체 서버 프로세스 강제 종료를 실행하지 않습니다. 이를 확장하려면 대상 서비스와 관측 프로세스를 컨테이너/별도 프로세스로 분리하고 운영체제 수준 계측을 추가해야 합니다.
